# Ticket-specific repair evidence

The automatic path supports one exact condition: `chat_title_zero_width`.
The user can select it in the support form. The persisted ticket must have
category `technical`, subject `チャットの見出しが空白になる`, and exactly one user
message whose body is
`チャットでゼロ幅スペース（U+200B）だけのメッセージを送ると、会話一覧の見出しが空白になります。`.
Files, administrator intervention, an extra user message, or any change to
that text makes the ticket ineligible. Other reports remain in review.

After the independent AI review completes successfully, the trusted `main`
workflow checks the private work/PR link and selects this exact condition.
Its comparison job receives only opaque identifiers, never a customer message
or production secret. It requires a draft PR with exactly
`src/lib/chat-thread.ts` and `src/lib/chat-thread.test.ts` changed. The PR
test has the opaque marker
`repair-regression:<first 16 hex of SHA-256(work_id)>:chat_title_zero_width`.
The comparison uses an independent test generated by trusted `main` code. It
checks that `createChatTitle("\u200B")` and `sanitizeChatTitle("\u200B")`
return `DEFAULT_CHAT_TITLE`. The same test must fail on the exact PR base and
pass on the exact head. The public artifact contains only opaque IDs, commit
hashes, test digests, and counts.

After the verified PR is merged and Vercel's production alias matches the
merge SHA, `ticket-repair-production-candidate.yml` re-reads the ticket and
release. Its isolated no-payment account sends the same single U+200B input
in a new chat through desktop Chrome, verifies the title and messages in the
database and page, reloads the page, and checks the title on mobile Chrome.
It also runs the general chat functional smoke. The synthetic account,
threads, and messages are deleted with two readbacks. Only then does the
trusted runner call `record_yutakasa_ticket_completion_proof` and read the
stored proof back. Completion/reply remains gated by the separate scheduled
20-minute observation and the current ticket state.

The older `chat_send_reload_persistence` and `chat_stream_completion`
scenarios still produce candidate evidence only. Their free-text reports do
not provide a replayable customer condition, so neither can record a
completion proof or send an automatic completion message.
